<h2>v0.0.0-beta.6 - Recipes, item icons and 3D rendering fixed</h2>

<p>This is the first update published to CurseForge since <strong>v0.0.0-beta.1</strong> (betas 2-5 were internal development builds and were never released here). It rolls up everything fixed since then, so updating from beta.1 brings in a large batch of stability and content fixes at once.</p>

<h3>Fix</h3>
<ul>
<li><strong>Auto Mechanic Table crafting restored</strong>: all 75 frame/wheel/engine/attachment recipes now parse and are craftable. They were previously all failing to load due to a recipe-format issue and, after that, a deeper item-registration-timing bug that has now been root-caused and fixed.</li>
<li><strong>Missing item icons fixed</strong>: all 20 items (blocks, <code>crowbar</code>, <code>automobile</code> and the component parts) now show a proper icon instead of the "missing texture" placeholder.</li>
<li><strong>3D item rendering restored</strong>: the automobile and its component items (frame/wheel/engine/attachments) render their real 3D model in hand, inventory and on the ground again, instead of appearing blank.</li>
<li><strong>Spanish translation</strong> (<code>es_es.json</code>) added.</li>
<li><strong>Automobile item hardening</strong>: fixed a potential crash and an oversized/degenerate render when placing an <code>automobile</code> item that has no crafted component data attached (e.g. obtained via search or <code>/give</code> rather than a crafted prefab).</li>
<li>Fixed a batch of first-real-playtest runtime crashes: data-generation event subscriptions, block/item id requirements, container and sound mixins, the vehicle-part entity-model loader (<code>jsonem</code>), networking payload registration, and slope blockstate definitions.</li>
</ul>

<h3>Known limitations in this beta</h3>
<ul>
<li>The banner pattern overlay on the rear attachment flag pole doesn't render yet (the pole itself does).</li>
<li>Passengers riding a vehicle don't visually tilt with the vehicle's motion.</li>
<li>The Auto Mechanic Table's recipe list only loads on singleplayer/server side; on a dedicated server the client-side recipe browser may appear empty until a proper sync packet is implemented.</li>
<li>The automobile speedometer HUD doesn't currently respect the F1 "hide GUI" toggle.</li>
</ul>

<blockquote>This is still a beta of the 26.2 port. Please report issues on the project page.</blockquote>

<h3>Requirements</h3>
<ul>
<li>Minecraft 26.2</li>
<li>NeoForge 26.2.0.37-beta+</li>
<li>Install on <strong>both client and server</strong></li>
</ul>
